# 2026-11-20 — The mail path map

## What was done

- **`takestock.mailpath`**, a new package and the `takestock mailpath`
  command (`docs/MAILPATH.md`):
  - `headers`: reads a header block (stopping at the body) into a route:
    each Received hop with its host, address, protocol, TLS version and
    cipher; how the message entered the mail system; the final receiver's
    authentication results; DKIM signatures; generating software; content
    protection from the outermost Content-Type; protective marking and
    sensitivity labels; the original author's domain from the first ARC seal
    when a list rewrote From.
  - `paths`: places each message as outbound, internal, inbound or a sender's
    copy and groups messages into flows by route, keeping counts and sizes per
    crossing.
  - `dmarc` and `cloudflare`: RFC 7489 aggregate reports and Cloudflare DMARC
    Management rows (fetched live in 30-day windows to the retention edge).
  - `trace`: Exchange Online message trace exports in two shapes.
  - `dnsposture`: MX, SPF, DMARC, DKIM, MTA-STS, TLS reporting, BIMI, DNSSEC
    and DANE per domain; MX probes reuse the STARTTLS collector.
  - `systems` and `data/mail-systems.yaml`: a catalogue of public mail
    services, with overlays for an organisation's own systems.
  - `report`: one page, every route drawn as boxes and arrows.
- `tools/guard-allow.txt`: public mail services' own host-name endings, so
  the catalogue and its tests can name them.
- README, changelog, `tests/test_mailpath.py`.

## Decisions taken while building

- A hop whose receiving server wrote plain `ESMTP` and no TLS clause is
  recorded as *not recorded*, not as cleartext: RFC 3848 says the keyword
  means no TLS, but servers write it regardless. Only the sending system's
  own log settles such a leg.
- A header the receiving platform stamps on mail it accepts is not evidence
  about the sender.
- An IP registry's organisation name does not identify a mail service, since
  a cloud provider's network carries its customers' hosts too; a DMARC source
  is named by reverse DNS or a declared range, else as `network: <owner>`.
