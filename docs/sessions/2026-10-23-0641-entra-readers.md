# 2026-10-23 — Six Microsoft Entra readers in the readers library

## What was done

- **`takestock.readers`** gains `entra_signins`, `entra_auth_methods`,
  `entra_workload_signins`, `entra_audit`, `entra_privileged_groups` and
  `entra_app_credentials`, with a shared helper module `readers/_entra.py`
  (heading matching, reading a file one row at a time, the download row
  limits, file settings that may be paths, lists or patterns, and the legacy
  client row two readers share). All are `general` with no default input.
- Settings with stated defaults: `entra_signins` takes `admin_names`
  (administrator name patterns) and three thresholds for when an
  application's sign-ins outside Conditional Access earn a row;
  `entra_audit` takes `failure_min_rows` (default 3) and
  `failure_material_share` (default 0.01); `entra_app_credentials` takes
  `date_format` (default ISO 8601) and `scope: directory-write`.
- `roles.py`: plain-language role phrases for the new rows.
- `docs/COLLECTORS.md`: a section for the six, the library table rows, and
  Microsoft Graph PowerShell scripts for the role assignment, group
  membership and application credential CSVs. The scripts were written from
  Microsoft's documentation and have not been run.
- Changelog.

Sources read on learn.microsoft.com: *How to download logs in Microsoft
Entra ID* (the per-file record limits; it does not say which rows a
download over the limit leaves out, so the readers do not claim to know),
*Learn about the sign-in log activity details* (a failed first factor
records a single-factor requirement, so only successful sign-ins are
counted as completing on one), *How to Use Conditions in
Conditional Access Policies* (modern and legacy client types), *Overview of
Conditional Access Authentication Strengths* (the phishing-resistant
methods). NZISM v3.9 16.7.42.C.01, C.05 and C.06 were read from the manual's
published CSV.

## Checks

- Tests on fixtures composed in the tests (synthetic accounts, IDs and
  2030 dates): one test file per reader, 48 tests.
- Thirty changes to the new code, each made in a scratch copy, were run
  against those tests: all 30 turned at least one test red (two did only
  after a test was added for them) and the unchanged copy stayed green.
- `make check`: guard, ruff, mypy and the full test suite, green.
